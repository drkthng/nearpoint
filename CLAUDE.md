# nearpoint

Personal research instrument that reimplements the published Polat / GlassesOff perceptual-learning
protocol for presbyopia: contrast detection of brief Gabor targets under lateral masking (collinear
flankers), crowding and backward masking, with adaptive difficulty.

- Background and evidence: `docs/research/oryx-near-vision-report.html`
- Protocol parameters (published values + our choices): `docs/protocol.md`
- Training program as data: `docs/curriculum.json`
- Status, next step and hand-offs: `docs/roadmap.md` (read first)
- Work plan for cloud sessions (scope and acceptance per session): `docs/sessions.md`

## Stack and target
- TypeScript (strict), Vite, Vitest. WebGL2 for stimuli; plain DOM for menus. No UI framework unless a session justifies it.
- Target: Samsung Galaxy S24 in Chrome (installed as PWA), landscape, 40 cm viewing distance, dim room.
  Device settings: Motion smoothness "Standard" (fixed 60 Hz), Screen mode "Natural" (≈ sRGB), adaptive
  brightness and Eye comfort shield off, brightness at maximum. Geometry always comes from calibration (pxPerMm).
- Secondary: desktop Chrome for development and debugging (needs a real ≥ 60 Hz refresh).
- Later (out of scope here): native Swift/Metal port.

## Commands
- `npm ci` install, `npm test` unit tests, `npm run typecheck`, `npm run build`, `npm run dev`

## Layout
- `src/core/`   pure logic, no DOM, fully unit-tested: staircase, observer, rng, geometry, luminance, protocol; later curriculum engine and trial state machine
- `src/render/` WebGL2 renderer plus a CPU reference renderer (the test oracle)
- `src/app/`    screens: start, calibration, training, outcome tests, history
- `src/data/`   IndexedDB storage, CSV export/import
- `docs/`       protocol, curriculum, sessions, session notes, research

## Non-negotiables
1. Stimulus durations are whole frames at the measured refresh rate (`framesFor`). Never use setTimeout/setInterval for stimulus timing.
2. Every trial logs the intended frame sequence and the requestAnimationFrame timestamps actually observed. A trial with any frame interval > 1.5x nominal is flagged invalid and does not update the staircase.
3. Contrast is Michelson contrast in linear luminance, encoded through `src/core/luminance.ts` (sRGB fallback, measured LUT later) with stochastic dithering. Never map contrast straight to RGB.
4. Geometry is specified in degrees and cycles/degree and converted with `pxPerDegree(distance, pxPerMm)` from calibration. Canvas backing stores are devicePixelRatio-exact; the browser must never rescale the stimulus.
5. GPU and CPU renderers implement identical math (`gaborValue`). The CPU renderer is the oracle for tests.
6. Training tasks and outcome tests are separate modules with separate stimuli; outcome tests are never generated by training code.
7. Any change to adaptive logic (staircase, curriculum) ships with simulated-observer tests using seeded RNG (`mulberry32`). No Math.random in `src/core` or in tests.
8. Data stays on the device (IndexedDB) with CSV export. No analytics, telemetry or runtime network calls.
9. UI copy makes no medical claims. The start screen says this is a personal research tool, not a medical device, and recommends an eye exam.

## Conventions
- Pure functions in `src/core`; side effects only in `src/app`, `src/render`, `src/data`.
- Tests sit next to code as `*.test.ts`. Keep `npm test` under about 30 s.
- New runtime dependencies need a stated reason; prefer none. Dev dependencies for testing are fine.
- If a parameter is not in `docs/protocol.md`, do not present an invented value as published: add it under "Our choices" with a rationale.

## How to work a session
0. Read `docs/roadmap.md` first: it says where the project is, which session to claim, and the hand-offs
   from earlier sessions. Claim your session there before starting and update it when done.
1. Read this file, `docs/sessions.md` (your session's section), `docs/protocol.md`, and the code you will touch.
2. Plan and list open questions before writing code.
3. Work directly on `main`: single-user project, no branches, no PRs. Commit in small steps and run
   `git pull --rebase origin main` before every push, so parallel sessions stack their commits.
4. Done means: acceptance criteria met, `npm test` and `npm run typecheck` green, and a short summary written to `docs/session-notes/<ID>.md` (do not edit other sessions' notes; parallel sessions must not conflict).

## Cloud environment
- Sessions run headless on Linux with no display. Verify rendering via the CPU reference renderer and unit tests; browser e2e (Playwright) runs in GitHub Actions.
- `scripts/cloud-setup.sh` installs dependencies through the SessionStart hook in `.claude/settings.json`.
