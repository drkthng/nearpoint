# S1 — Rename to nearpoint, stimulus layout and renderers

## Built
- Renamed the project to "nearpoint" (package.json, package-lock.json, README, CLAUDE.md, index.html, scripts/cloud-setup.sh). The research report keeps its file name and its prose about the Oryx "near-vision trainer".
- `src/core/layout.ts`: pure patch layouts for SINGLE, LM, CROWD and the BM-* conditions; `stimulusPatches`, `maskPatches`, `barAxis`, `carrierAxis`, `carrierRad`, `baseLayout`, `maskLayout`.
- `src/render/cpu.ts`: CPU reference renderer (`renderCpu`), pure TS, returns RGBA codes and linear luminance. Test oracle.
- `src/render/webgl.ts`: thin WebGL2 renderer (`WebGLStimulusRenderer`), pure `packPatches` (max 12 patches), `fragCoordToTopLeft`, `backingSize`, `fitCanvasToDevicePixels` (ResizeObserver with devicePixelContentBoxSize, fallback to CSS size × devicePixelRatio).
- `src/render/gabor.frag.glsl`: `precision highp int`, integer PCG dither hash keyed by pixel and a `uint uSeed` (replaces the sin-based hash), 3.5σ support cutoff matching the CPU renderer.
- `debug.html` + `src/app/debug.ts` + `src/app/debug-params.ts`: static stimulus from URL parameters (condition, cpd, theta, sep, tc, fc, nflank, distanceCm, pxPerMm, mean, seed, frame=target|mask, present), WebGL2 with CPU fallback via putImageData, readout of px/deg, λ, σ, renderer, devicePixelRatio, backing size. Second Vite build entry.

## Key decisions
- Coordinates: device pixels, origin top-left, y down; pixel (x, y) has centre (x + 0.5, y + 0.5). The shader's p = (gl_FragCoord.x, H − gl_FragCoord.y) equals that centre (tested via `fragCoordToTopLeft`).
- θ = bar orientation, 0 = vertical. Bar axis b = (sin θ, −cos θ), carrier c = (cos θ, sin θ); renderer carrier angle = θ in radians, consistent with `gaborValue`.
- LM: flankers at centre ± dλ·b. CROWD: 3×3 grid i·dλ·b + j·dλ·c, n ∈ {2, 4, 6, 8}, order collinear pair, pair along c, diagonals; other counts throw. More than 8 flankers left undefined (Open questions in protocol.md).
- BM mapping: BM-T → SINGLE target frame, mask = collinear pair; BM-LM → LM, mask = same pair; BM-CROWD → CROWD, mask = same crowd array. SINGLE has no mask frame.
- Target absent: target patch omitted, flankers unchanged.
- Patch support 3.5σ in both renderers; default mean luminance 0.214 linear (sRGB mid-grey); σ = λ by default.
- All new choices recorded under "Our choices" in docs/protocol.md.

## Tests
- 41 tests in 5 files, about 2.5 s. `npm run typecheck` and `npm run build` green; dist/ contains index.html and debug.html.
- Layout: flankers on the bar axis and at d·λ within 0.01 px for 0/45/90/135°, exact CROWD offsets and order, no duplicates, invalid counts and parameters throw, BM mapping.
- CPU renderer: Michelson contrast within 0.5 % (σ = 20λ so the envelope is flat over ±λ/2; with σ = λ the envelope lowers measured Michelson to C(1+e)/(2+C(1−e)), e = exp(−1/8), also tested); bars run along barAxis for all four orientations; far field equals the mean; dithered uniform field within 0.01 code values; patch-region dither bias < 0.05; determinism; clamping.
- WebGL: uniform packing (lengths, order, padding, > 12 throws), shader contract strings, pixel-centre mapping, backing size rounding.
- No dev or runtime dependencies added.

## Open issues
- The GLSL has not been compiled anywhere (no display in cloud sessions). First real check is the browser / CI.
- CPU dither uses mulberry32, GPU uses PCG: same distribution, different stream. The GPU has no dither-off mode, so GPU vs CPU can only be compared statistically.
- Crowding layouts with more than 8 flankers are undefined.
- `fitCanvasToDevicePixels` and the WebGL draw path have no unit tests (DOM/GPU only).

## Suggestions
- S2 (trial engine): build each interval from `stimulusPatches` (target frame) and `maskPatches` (BM mask frame); omit the target in the blank interval; pass a fresh seed to `WebGLStimulusRenderer.draw` every frame; keep using `fitCanvasToDevicePixels` for the stimulus canvas.
- S8 (GPU vs CPU in CI): load `debug.html?…&seed=…` in Playwright, fail on shader compile errors, read back pixels and compare with `renderCpu` for the same parameters: mean code per region within dither noise, and Michelson contrast of the linear-decoded field. Consider adding a `uDither` uniform (u = 0.5) for an exact pixel comparison.
