# S5 — App shell, calibration, training flow

## Built
- Pure core (tested): `src/core/calibration.ts` (card → device px/mm, blind-spot distance, refresh estimate
  and warnings), `src/core/block-runner.ts` (`BlockRunner`: per-trial draws, staircase updated only on
  timing-valid trials, block ends after N valid or 1.5×N attempts, `discard()` for aborted trials),
  `src/core/results.ts` (past thresholds, relative index, contrast formatting), `src/core/chart.ts`
  (inline-SVG log-contrast chart).
- App (plain DOM, hash router): `index.html`, `src/main.ts`, `src/app/{routes,dom,context,download,audio,frames}.ts`,
  screens `start` (disclaimer, calibration status, next session plan, backup reminder, storage persistence),
  `calibrate` (S24 checklist, ID-1 card matching, distance, optional blind-spot check, refresh measurement),
  `train` (full session runner), `history` (completed sessions table + threshold chart; aborted/test runs
  collapsed), `data` (CSV export, JSON backup, restore).
- Training session: pre-session plan card → fullscreen/landscape/wake-lock attempts → session-start refresh
  measurement (all frame counts use it) → per block: intro card, 2IFC trials via `playFrames` + WebGL2
  (`framePatches`, new dither seed every frame, 0.7° fixation ring), tap left/right half or keys 1/2,
  auditory + visual feedback, timing-invalid trials shown as "Timing glitch — not counted" and counted on
  screen → block results card (threshold, relative index, valid/invalid) → session summary.
  Every trial is persisted as it completes, with its stored timing log.
- Test hook: `#train?quick=1&auto=1&trials=N` runs short blocks with an automatic responder; such sessions
  are saved as aborted ("quick mode (test run)") and never enter the training history.
- Data layer additions: `onVersionChange` hook (reload banner), CSV columns `abort_reason`, `rng_seed`,
  `app_version`, `flanker_contrast`.

## Key decisions
- Refresh is re-measured at every session start; a mismatch with the calibration and any rate other than
  60 Hz is shown as a warning. WebGL2 is required for training (no CPU fallback: too slow for frame-exact
  presentation).
- Two seeded streams from one stored `rngSeed` (crypto): trial draws and per-frame dither seeds, so trial
  sequences are replayable from the seed.
- Hidden tab or canvas resize mid-trial aborts the trial (discarded, not counted) and pauses the session.
- At boot, sessions left "in-progress" are marked aborted ("interrupted"); stopping or leaving writes partial
  block counts first.
- Block length, per-trial draws, relative index, card calibration and blind-spot check are recorded under
  "Our choices" in docs/protocol.md.

## Tests and verification
- 156 unit tests in 22 files, about 2.5 s; typecheck and build green.
- Simulated observer through `BlockRunner` (100 seeds): mean log threshold within 0.006 of the true 70.7 %
  point; all-invalid trials never move the staircase.
- End-to-end in headless Chromium (SwiftShader) during the session: calibrate via UI, quick session of
  4 blocks × 4 trials completes in about 35 s with all rows persisted; Stop (mid-block and on a card),
  reload mid-session, leaving via the hash, and the pause path all leave consistent data; History shows the
  quick run under "Aborted and test sessions". Scripts lived in /tmp (not committed; S8 owns e2e in CI).

## Open issues
- Not yet run on the Galaxy S24: touch response, fullscreen, wake lock, fixation ring at DPR ≈ 2.6, refresh
  stability at "Standard" 60 Hz. Under SwiftShader 0–4 of 16–19 trials were timing-invalid; real hardware
  should be far better — check the invalid counts on the phone.
- Resize-mid-trial abort is implemented but not exercised end to end.
- At boot every "in-progress" session is marked aborted, including one running in a second tab (single-user
  app; acceptable).
- Tapping the screen to answer can move a phone stand; consider a Bluetooth keyboard/remote (keys 1/2 work).
- Feedback tones need a real user gesture (normal use has one; auto mode logs a browser warning).
