# S3 — Curriculum engine

## Built
- `src/core/curriculum.ts`: `nextSession(curriculum, history)` returns the next `SessionPlan`
  (params {cpd, θ}, template blocks with those params, change kind, human-readable reason) or a stop decision
  ("plateau" / "max_sessions reached"). Helpers `sessionScore`, `isPlateau`, `nextCpd`, `nextOrientation`,
  constants `CPD_LADDER` [2, 3, 4, 6, 8], `ORIENTATION_CYCLE`, `PLATEAU_MARGIN_LOG10` = 0.01.
- `src/core/curriculum-sim.ts`: `simulateProgram(curriculum, model, seed)` runs a whole program with a Weibull
  observer (factors per condition, cpd and oblique orientation; illustrative, not published), the real
  `Staircase` and the curriculum engine, all from one mulberry32 stream.
- Dev dependency: fast-check ^4.10.2, for seeded property-based tests of the curriculum invariants
  (allowed by docs/sessions.md S3).

## Key decisions (all under "Our choices" in docs/protocol.md)
- One `{cpd, θ}` per session, applied to every template block; within a block each trial draws sep_lambda and
  isi_ms uniformly from the block's lists, one staircase per block.
- Orientation rotates every 2 sessions (0-based index 2, 4, …); rotation has priority, a due cpd raise is
  re-evaluated in the next session. Rotating every session is rejected with one-change-per-session.
- cpd raised one ladder step when the previous session's score (geometric mean of converged block thresholds)
  is < 0.05.
- Plateau: from session 25 on, stop when the mean log10 score of the last 4 scored sessions at the current cpd
  improves on the 4 before by < 0.01 log10 (needs 8 scored sessions at that cpd). Stop at 65 regardless.
  The first version (best-of-window with a 0.02 margin) stopped even improving observers at 25; the review
  caught it.

## Tests
- 100 tests in 12 files, about 2.7 s; typecheck green.
- Unit tests for every rule (first session, rotation, cpd raise and deferral, both-changes mode, score,
  plateau, min/max stops, invalid curriculum, deep copy, rotation guard).
- Property tests (fast-check, seed 42, 200 runs, varied progression settings and null scores): at most one of
  cpd/θ changes per session, cpd on the ladder and never decreasing, rotation timing and cycle, stop rules;
  counters prove rotations (1981), cpd raises (247), deferred raises (140), plateau stops (7) and max stops (84)
  actually occurred.
- Simulation, seeds 1–20: learning observer (2 %/session) runs 25–42 sessions, median 34.5, 15/20 longer than
  25, all raise cpd (15 end at 8 cpd); flat observer median 25.

## Open issues
- The criterion (5 %), ladder, plateau window and margin are placeholders; revisit with real data.
- `BlockResult` has optional `blockIndex`, `validTrials`, `invalidTrials` for S5/S4 to fill; the engine ignores
  them for now.
- Simulated thresholds have no between-session noise beyond the staircase; real data will be noisier.

## Suggestions
- S5: call `nextSession(curriculum, history)` at session start, show `plan.reason` on the start card, run each
  block with its own `Staircase` (curriculum.staircase), draw sep/ISI per trial with the seeded RNG, record
  `{condition, threshold, blockIndex, validTrials, invalidTrials}` per block (only valid trials update the
  staircase). Show "program complete" when `stop` is returned.
- S4: store `SessionRecord` (params + block results) and the `SessionPlan` (including `reason`) per session;
  history for `nextSession` is the ordered list of completed sessions.
